# 构建与烧录

> [← 返回项目首页](../README.md) · [硬件与接线](硬件与接线.md) · [技术深潜](技术深潜.md)

本工程从 Keil/ARMCC 迁移到了 **CMake + Ninja + arm-none-eabi-gcc**，不依赖任何 IDE，命令行即可完整编译。

## 1. 环境要求

| 工具 | 版本 / 说明 |
|---|---|
| CMake | ≥ 3.22（`CMakeLists.txt` 中的最低要求） |
| Ninja | 由 `CMakePresets.json` 指定为生成器 |
| GNU Arm Embedded Toolchain | `arm-none-eabi-gcc` 需在 PATH 中，提供 gcc / g++ / objcopy / size |
| 烧录工具 | ST-Link + OpenOCD，或 STM32CubeProgrammer |
| VOFA+（可选） | 上位机波形显示，用于看遥测数据 |
| STM32CubeMX（可选） | 需要改外设配置时打开 `balanceCar.ioc` |

目标芯片：STM32F103C8T6，Cortex-M3 @ 72 MHz，64 KB Flash / 20 KB RAM。链接脚本为根目录的 `STM32F103C8Tx_FLASH.ld`。

## 2. 编译

```bash
cmake --preset Debug
cmake --build --preset Debug
```

预设由 `CMakePresets.json` 定义，`build/Debug/` 是构建目录。可用的构建类型：`Debug`、`Release`、`RelWithDebInfo`、`MinSizeRel`，替换命令中的 `Debug` 即可。

生成可烧录文件：

```bash
arm-none-eabi-objcopy -O ihex   build/Debug/balanceCar.elf build/Debug/balanceCar.hex
arm-none-eabi-objcopy -O binary build/Debug/balanceCar.elf build/Debug/balanceCar.bin
arm-none-eabi-size             build/Debug/balanceCar.elf
```

使用 CLion 时直接打开项目并选择 `Debug` 预设即可，不需要额外配置。

## 3. 用户代码登记在哪

- `CMakeLists.txt` 的 `target_sources()` 登记了 5 个用户源文件（`pid.c`、`motor.c`、`encoder.c`、`sr04.c`、`oled.c`）和 4 个 `MyCode/` 下的 MPU6050/DMP 驱动；新增源文件要加到这里，否则链接时会报 `undefined reference`。
- `cmake/stm32cubemx/CMakeLists.txt` 是 CubeMX 生成的 Cube 源文件与 HAL 源文件清单；`cmake/gcc-arm-none-eabi.cmake` 是编译与链接选项（`-mcpu=cortex-m3`、`--specs=nano.specs`、`-u _printf_float` 等）。
- `Drivers/` 下 700 多个文件是 ST 官方 HAL/CMSIS，不需要、也不应该修改。

## 4. 烧录

**ST-Link + OpenOCD（推荐）**

```bash
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg \
  -c "program build/Debug/balanceCar.elf verify reset exit"
```

**STM32CubeProgrammer**：ST-Link 接 SWD → 连接 → 选择 `build/Debug/balanceCar.hex` → Download → 校验 → 复位。

> 注意：初始化代码里调用了 `__HAL_AFIO_REMAP_SWJ_NOJTAG()`，**JTAG 已被禁用**，只能用 SWD（PA13/PA14）。用 JTAG 接口连接会失败，这不是接线坏了。

## 5. 上电自检

1. OLED 显示 `Init Sucess`，随后刷新 `roll` 与 `distance`（无有效回波时显示 `D:--`）。
2. 松手后车能自己立住；轻推一下能走回原位。
3. 蓝牙遥控（USART3，9600 波特，单字节指令）：

   | 字节 | 动作 |
   |---|---|
   | `W` (0x57) | 前进并回正 |
   | `S` (0x53) | 后退并回正 |
   | `A` (0x41) | 左转，保持行驶 |
   | `D` (0x44) | 右转，保持行驶 |
   | `T` (0x54) | 全部停止 |

4. VOFA+ 选择 **FireWater** 协议、9600 波特，遥测帧为逗号分隔、换行结尾的 7 个通道：

   | # | 通道 | 单位 / 说明 |
   |---|---|---|
   | 1 | `roll` | 倾角（度） |
   | 2 | `gyrox` | 角速度（陀螺仪原始值） |
   | 3 | `Vertical_out` | 直立环输出（PWM） |
   | 4 | `Velocity_out` | 速度环输出（度） |
   | 5 | 轮速 | 左右编码器之和 |
   | 6 | `stop` | 摔倒保护标志 |
   | 7 | `Control_dt_ms` | 实测控制周期（ms） |

   **第 7 路是自查工具**：应稳定在 8.9 附近。若明显偏离或跳变，先查 MPU6050 的 INT 引脚（PB5）接线与 DMP 初始化，不要急着调 PID 参数。

## 6. 常见坑

| 现象 | 原因 |
|---|---|
| OLED 和遥测里的 `%.2f` 输出为空，编译却不报错 | GCC + newlib-nano 默认不链接浮点 printf。`cmake/gcc-arm-none-eabi.cmake` 已显式加了 `-u _printf_float`，从 Keil/ARMCC 移植时最容易漏掉这一条 |
| 报 `undefined reference to _exit` / `_sbrk` | newlib 需要 syscalls 实现，`Core/Src/syscalls.c`、`sysmem.c` 必须留在构建清单里 |
| 找不到生成器或编译器 | Ninja 或 `arm-none-eabi-*` 不在 PATH |
| Flash 放不下 | 换 `Release`（`-Os`），并用 `arm-none-eabi-size` 看占用 |
| CubeMX 重新生成后改动丢失 | 只写在 `USER CODE BEGIN/END` 区段内；`pid.c` 等独立用户文件不会被覆盖，但要在 `CMakeLists.txt` 里登记 |
| 车完全不动、控制周期异常 | 先查 MPU6050 INT → PB5 的中断线，控制节拍完全依赖它 |

## 7. 参数在哪里改

| 位置 | 内容 |
|---|---|
| `Core/Src/pid.c` 顶部 | 三环增益、`Med_Angle`、各类限幅宏、`OBSTACLE_CM`、`SPEED_Y` / `SPEED_Z`、`TURN_SIGN` |
| `Core/Src/tim.c` | TIM1 PWM 周期 7200（10 kHz）、TIM2/TIM4 编码器 `IC1Filter/IC2Filter = 15` |
| `Core/Src/usart.c` | `BT_BAUD` 蓝牙波特率 |
| `Core/Src/main.c` | `BT_DECIM` 遥测抽取比（5 → 约 20 Hz）、`BT_OLED_MS` 屏幕刷新间隔 |

> 改 `TURN_SIGN` 后必须做一次悬空验证：把车拿在手里、两轮离地，目标转速为 0 时用手把车身往左拧，轮子应"抵抗"这个旋转；若反而帮忙往左转，说明符号反了，车会越转越快。方法写在 `pid.c` 的注释里。
