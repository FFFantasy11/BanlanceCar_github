## 2. 引脚分配

| 功能 | 引脚 / 外设 | 备注 |
|---|---|---|
| MPU6050 软件 I2C | PB3 / PB4 | 释放 JTAG 后才能使用 |
| MPU6050 中断 | PB5 → EXTI9_5 | **控制节拍的唯一来源**，接到 `Control()` |
| OLED 硬件 I2C | PB8 / PB9（I2C1 重映射） | 默认脚被 TIM4 占用，见下节 |
| 左轮编码器 | TIM2 CH1/CH2 → PA0 / PA1 | TI12 模式，双边沿计数，输入滤波 15 |
| 右轮编码器 | TIM4 CH1/CH2 → PB6 / PB7 | TI12 模式，双边沿计数，输入滤波 15 |
| 电机 PWM | TIM1 CH1 / CH4 | 周期 7200 → 10 kHz |
| 电机方向 | PB12 / PB13 / PB14 / PB15 | TB6612 的 IN1/IN2 |
| 蓝牙 | USART3 TX PB10 / RX PB11 | 9600 波特 |
| 超声波 | Trig PA3 / Echo PA2 | TIM3 用于测量回波脉宽 |
| 调试下载 | SWD：PA13 / PA14 | JTAG 已禁用 |

完整配置以 `balanceCar.ioc` 和 `Core/Src/gpio.c`、`tim.c`、`i2c.c` 为准。

## 3. 两个容易踩的硬件资源冲突

这块芯片的引脚比较紧，有两处必须靠复用重映射才能共存，也是接线排查时最容易误判的地方：

1. **I2C1 与 TIM4 编码器抢 PB6/PB7**。I2C1 默认脚正是 PB6/PB7，但这两个脚给了右轮编码器，所以 OLED 必须调用 `__HAL_AFIO_REMAP_I2C1_ENABLE()` 重映射到 **PB8/PB9**（在 `Core/Src/i2c.c` 的 MSP 初始化里）。
2. **MPU6050 的软件 I2C 需要 PB3/PB4**，而这两个脚默认是 JTAG 的 JTDO / NJTRST。代码里用 `__HAL_AFIO_REMAP_SWJ_NOJTAG()` 禁用 JTAG、保留 SWD，代价是**下载调试只能用 SWD 两线**。

另外，编码器线与电机线相邻，而电机 PWM 是 10 kHz。TIM2/TIM4 的编码器输入滤波必须从默认的 `0` 改成 `15`，否则毛刺会被计入速度环——这个修复让直立环可用增益提升了 30%，完整分析见 [技术深潜](技术深潜.md)。

## 4. 实测常数（复现时请重新标定）

| 常数 | 本车实测值 | 测法 |
|---|---|---|
| 控制周期 | 8.9 ms（约 112 Hz） | `HAL_GetTick()` 对 100 次中断取平均，遥测第 7 通道实时显示 |
| 编码器刻度 | 8197 计数 / 米 | 手推恰好 1.00 m，读 `Speed_Pos_Raw`（不受限幅的副本） |
| 机械中心角 `Med_Angle` | 2.20° | 跑起来后取 `roll` 平均值 |
| 电机突破 PWM | 约 350 / 7200 = 4.86% | 空载逐步加 PWM，观察起转点 |

> 换电机、换轮子、甚至换地面，都建议重新测一遍。推算值 8790 与实测值差 7%，而如果编码器线数不是标称的 11 PPR，推算误差会达到 1.5~2 倍，足以让环路从"刚好稳定"变成发散。

## 5. 上电前检查清单

- [ ] 电机线序：给一个小的正 PWM，两轮都应向前转；有一边反了就调换该电机线或改方向引脚
- [ ] 编码器符号：手推车向前 1.00 m，`Speed_Pos_Raw` 的变化量应约为 8197；若为负或明显偏小，检查 TI12 接线与符号
- [ ] `TURN_SIGN` 悬空验证（方法见 [构建与烧录](构建与烧录.md) 第 7 节）
- [ ] MPU6050 安装方向：`roll` 应为左右倾斜角，前倾时符号与 `Vertical_Kp` 的负号配套
- [ ] 电池电压充足；低电压下死区补偿和转向表现会变差
- [ ] 超声波 Trig/Echo 接线；OLED 上 `distance` 长期不变说明无回波
- [ ] 确认使用 SWD 下载，不要接 JTAG
